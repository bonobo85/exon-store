🔐 Guide Implémentation Sécurité - Exon Store

📌 Résumé: Ce guide vous montre comment intégrer la sécurité dans vos pages HTML existantes.

1️⃣ Setup Initial (5 minutes)

Étape 1: Vérifier les fichiers de sécurité

Assurez-vous que ces fichiers existent dans ./js/:

  • ✅ security-utils.js - Utilitaires côté client
  • ✅ security-init.js - Initialisation des protections
  • ✅ security-middleware.js - Middleware serveur
  • ✅ api-integration.js - Exemples d'intégration
  • ✅ server.js - Serveur avec sécurité

Étape 2: Charger les scripts de sécurité dans vos pages HTML

⚠️ IMPORTANT: L'ordre des scripts est CRITIQUE !

Chaque page HTML doit avoir ces scripts dans <head> ou avant </body>:

<!-- 1️⃣ SÉCURITÉ - Charger EN PREMIER -->
<script src="/js/security-utils.js"></script>

<!-- 2️⃣ Initialisation des protections -->
<script src="/js/security-init.js"></script>

<!-- 3️⃣ Exemples d'intégration API -->
<script src="/js/api-integration.js"></script>

<!-- 4️⃣ Votre script applicatif -->
<script src="/js/app.js"></script>

2️⃣ Meta Tags de Sécurité

Ajouter ces meta tags dans le <head> de toutes les pages:

<!-- Content Security Policy -->
<meta http-equiv="Content-Security-Policy" content="
    default-src 'self';
    script-src 'self' 'unsafe-inline' cdn.jsdelivr.net;
    style-src 'self' 'unsafe-inline' cdn.jsdelivr.net;
    img-src 'self' data: https: blob:;
    font-src 'self' cdn.jsdelivr.net;
    connect-src 'self' https://firebase.google.com;
    frame-src 'none';
    object-src 'none';
    form-action 'self';
    upgrade-insecure-requests;
">

<!-- Prevent clickjacking -->
<meta http-equiv="X-UA-Compatible" content="IE=edge">

<!-- Disable MIME sniffing -->
<meta http-equiv="X-Content-Type-Options" content="nosniff">

<!-- XSS Protection -->
<meta http-equiv="X-XSS-Protection" content="1; mode=block">

<!-- Referrer Policy -->
<meta name="referrer" content="strict-origin-when-cross-origin">

3️⃣ Mise à Jour des Formulaires

Avant (NON-SÉCURISÉ):

document.getElementById('form').addEventListener('submit', async (e) => {
    e.preventDefault();
    const email = document.getElementById('email').value;
    
    // ❌ Pas de validation
    // ❌ Pas de protection CSRF
    // ❌ Fetch direct sans sécurité
    fetch('/api/register', {
        method: 'POST',
        body: JSON.stringify({ email })
    })
});

Après (SÉCURISÉ):

document.getElementById('form').addEventListener('submit', async (e) => {
    e.preventDefault();
    const email = document.getElementById('email').value.trim();
    
    // ✅ Validation email
    if (!validateEmail(email)) {
        alert('Email invalide');
        return;
    }
    
    // ✅ Détecte injection
    if (detectInjectionAttempt(email)) {
        alert('Entrée invalide');
        return;
    }
    
    // ✅ Envoi sécurisé (token CSRF ajouté automatiquement)
    const response = await secureAPI('/api/register', {
        method: 'POST',
        body: JSON.stringify({ email })
    });
    
    if (response.ok) {
        const data = await response.json();
        console.log('Succès:', data);
    }
});

4️⃣ Appels API Sécurisés

Type d'Appel Utiliser Protection
Enregistrement secureRegister() Validation + Rate Limit + CSRF + Hash
Connexion secureLogin() Brute Force Protection + CSRF
Déconnexion secureLogout() Session + Nettoyage tokens
Panier secureSaveCart() Validation données + CSRF
Upload secureUploadFile() Validation fichier + Rate Limit + CSRF
Autres requêtes secureAPI() CSRF + Erreur handling

Exemple: Formulaire de Connexion

<form id="loginForm">
    <input type="email" id="email" required>
    <input type="password" id="password" required>
    <button type="submit">Se connecter</button>
</form>

<script>
document.getElementById('loginForm').addEventListener('submit', async (e) => {
    e.preventDefault();
    
    const email = document.getElementById('email').value.trim();
    const password = document.getElementById('password').value;
    
    // Utilise la fonction d'intégration sécurisée
    const result = await secureLogin(email, password);
    
    if (result.success) {
        console.log('Connecté:', result.user);
        window.location.href = '/category/home.html';
    } else {
        alert(result.message);
    }
});
</script>

5️⃣ Affichage Sécurisé des Données

❌ DANGEREUX - N'utilisez PAS:

// Risque XSS - les balises HTML sont exécutées
document.getElementById('user-name').innerHTML = userData.username;

✅ SÉCURISÉ - À Utiliser:

// Option 1: textContent (recommandé pour le texte simple)
document.getElementById('user-name').textContent = userData.username;

// Option 2: innerHTML avec escapeHTML (si besoin)
document.getElementById('user-name').innerHTML = escapeHTML(userData.username);

// Option 3: createTextNode (vanille)
const node = document.createTextNode(userData.username);
document.getElementById('user-name').appendChild(node);

6️⃣ Stockage Sécurisé des Données

Pour les données sensibles (tokens, sessions):

// Sauvegarde avec expiration (30 minutes)
SecureStorage.setSecure('sessionToken', token, 30);

// Récupère (retourne null si expiré)
const token = SecureStorage.getSecure('sessionToken');

// Supprime
SecureStorage.removeSecure('sessionToken');

Pour les données publiques:

// Peut utiliser localStorage directement
localStorage.setItem('userPreferences', JSON.stringify(prefs));
const prefs = JSON.parse(localStorage.getItem('userPreferences'));

7️⃣ Validation des Entrées

Type Fonction Exemple
Email validateEmail() validateEmail('user@example.com') → true
Mot de passe validatePassword() validatePassword('Secure@123') → true
Username validateUsername() validateUsername('user_123') → true
Texte général sanitizeInput() sanitizeInput('Hello world') → 'Hello world'
Injection XSS detectInjectionAttempt() detectInjectionAttempt('<script>') → true

8️⃣ Protection Brute-Force

// Enregistrer une tentative
if (!bruteForceProtection.recordAttempt(email)) {
    alerts('Trop de tentatives, veuillez réessayer plus tard');
    return;
}

// Vérifier si bloqué
if (bruteForceProtection.isBlocked(email)) {
    alert('Compte temporairement bloqué');
    return;
}

// Obtenir le nombre de tentatives restantes
const left = bruteForceProtection.getAttemptsLeft(email);
console.log(`Tentatives restantes: ${left}`);

// Réinitialiser après succès
bruteForceProtection.reset(email);

9️⃣ Débogage & Testing

Accès aux utilitaires de sécurité en console:

// Dans la console navigateur (F12):

// Valider email
SecurityDebug.validateEmail('test@test.com')

// Valider mot de passe
SecurityDebug.validatePassword('Secure@123')

// Échapper HTML
SecurityDebug.escapeHTML('<script>')

// Détecter injection
SecurityDebug.detectInjectionAttempt('alert(1)')

// Obtenir le token CSRF
csrfTokenManager.getToken()

// Voir protection brute-force
bruteForceProtection.getAttemptsLeft('email@test.com')

🔟 Checklist d'Implémentation

Pour chaque page HTML:

  • ☐ Scripts de sécurité chargés dans le bon ordre
  • ☐ Meta tags CSP ajoutés
  • ☐ Formulaires utilisent secureAPI() ou fonctions d'intégration
  • ☐ Validations côté client implémentées
  • ☐ innerHTML remplacé par textContent quand possible
  • ☐ Pas de mots de passe en clair dans le code
  • ☐ Pas d'appels fetch directs (utiliser secureAPI)
  • ☐ Données sensibles en SecureStorage

1️⃣2️⃣ Dépannage

Problème: "security-utils is not defined"

Solution: Vérifiez que security-utils.js est chargé EN PREMIER, avant les autres scripts.

Problème: CSRF token invalide

Solution:
  • Actualiser la page (les tokens se renouvellent automatiquement)
  • Vérifier que security-init.js est chargé
  • Vérifier la console pour les erreurs

Problème: CSP violations

Solution:
  • Ouvrir la console (F12)
  • Chercher les messages CSP violations
  • Ajouter le domaine manquant à la whitelist CSP
  • Remplacer les scripts inline par externes si possible
